# cpplint Configuration Rationale

## Goal: Suggest Improvements, Not Downgrades

This configuration enables cpplint to suggest code quality improvements rather than lowering standards by disabling helpful checks.

## Configuration Choices

### Enabled Checks (Quality Improvements)

1. **Include Order** (`build/include_order`) - **ENABLED**
   - **Why**: Proper include order (main.h → C system → C++ system → other) helps catch missing includes and separates standard library from third-party dependencies
   - **Improvement**: Better maintainability, fewer hidden dependencies

2. **Line Length** (100 characters) - **ENABLED with reasonable limit**
   - **Why**: Lines should have a reasonable length for readability
   - **Improvement**: 100 chars is a good modern compromise (not the strict 80 from decades ago)

3. **Casting Style** (`readability/casting`) - **ENABLED**
   - **Why**: Suggests `static_cast<T>()` instead of C-style `(T)` casts
   - **Improvement**: Type safety, clearer intent, catches errors at compile time

4. **Comment Spacing** (`whitespace/comments`) - **ENABLED**
   - **Why**: Suggests proper spacing between code and comments
   - **Improvement**: Better readability

5. **File Ending** (`whitespace/ending_newline`) - **ENABLED**
   - **Why**: POSIX standard requires newline at end of file
   - **Improvement**: Standards compliance, prevents issues with some tools

6. **Include What You Use** (`build/include_what_you_use`) - **ENABLED**
   - **Why**: Suggests explicit includes for symbols used (e.g., `#include <utility>` for `std::move`)
   - **Improvement**: Explicit dependencies, less fragile code

### Disabled Checks (Not Applicable)

1. **C++11/C++17 Version Checks** (`-build/c++11,-build/c++17`)
   - **Why disabled**: Project uses C++20 features (`<filesystem>`, structured bindings, ranges, etc.)
   - **Not a downgrade**: These version warnings don't apply to a C++20 project

## Comparison with Previous Configuration

### Previous (Downgrade)
```yaml
args:
  - "--filter=-build/include_order,-build/c++11,-whitespace/line_length"
```

**Problems:**
- ❌ Disabled include order checking → worse code organization
- ❌ Disabled line length checking → readability issues
- ❌ Only disabled C++11 but code uses C++17 → ineffective

### Current (Improvement)
```yaml
args:
  - "--filter=-build/c++11,-build/c++17"
  - "--linelength=100"
```

**Benefits:**
- ✅ Enables include order checking → better organization
- ✅ Enables line length with reasonable limit → better readability
- ✅ Disables both C++11 and C++17 warnings → appropriate for C++20 project
- ✅ Enables all other quality checks → code improvements

## Summary

This configuration treats cpplint as a tool to **improve** code quality by:
- Enforcing best practices (include order, casting style)
- Maintaining readability (line length, comment spacing)
- Ensuring standards compliance (file endings, explicit includes)

The only disabled checks are version warnings that don't apply to a C++20 codebase.
